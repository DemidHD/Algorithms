# Лабораторные работы по алгоритмам

Реализации четырёх классических алгоритмов на Python с вводом данных с клавиатуры, визуализацией результата и пошаговой анимацией.

| Файл | Алгоритм | Задача | Сложность |
|---|---|---|---|
| `dijkstra.py` | Алгоритм Дейкстры | Кратчайшие пути от одной вершины | O((V + E) log V) |
| `tarjan.py` | Алгоритм Тарьяна | Компоненты сильной связности | O(V + E) |
| `ford_fulkerson.py` | Алгоритм Форда-Фалкерсона | Максимальный поток в сети | O(E · F) |
| `graham.py` | Алгоритм Грэхема | Выпуклая оболочка точек | O(n log n) |

Здесь V — число вершин, E — число рёбер, F — величина максимального потока, n — число точек.

## Запуск

Нужен Python 3.10+. Сами алгоритмы написаны без сторонних библиотек. Для визуализации и анимации нужны `matplotlib` и `networkx` (список — в `requirements.txt`):

```bash
pip install -r requirements.txt
```

```bash
python dijkstra.py
```

После запуска программа спрашивает, использовать ли встроенный пример:
- `y` — запускается на заранее заданных данных;
- `n` — данные вводятся с клавиатуры (формат описан ниже для каждой программы).

Некорректный ввод (не число, неверное количество значений, несуществующая вершина и т. п.) не приводит к падению программы — выводится сообщение об ошибке и значение запрашивается повторно.

После вывода результата появляется меню визуализации:

```
Визуализация:
  1 — итоговый результат
  2 — пошаговая анимация
  3 — сохранить анимацию в GIF
  0 — выход
```

- **1 — итоговый результат**: окно с рисунком результата; картинку можно сохранить кнопкой с дискетой в этом окне.
- **2 — пошаговая анимация**: окно, в котором алгоритм проигрывается по шагам. Над рисунком написано, что происходит на текущем шаге и почему, внизу слева — состояние структур данных (куча, стек и т. п.), справа — номер шага.
- **3 — сохранить анимацию в GIF**: те же шаги сохраняются в файл `<имя_алгоритма>.gif` в текущей папке — удобно вставить в отчёт.

Управление пошаговой анимацией:

| Кнопка | Клавиша | Действие |
|---|---|---|
| `< Назад` / `Вперёд >` | ← / → | шаг назад / вперёд |
| `Авто` / `Пауза` | пробел | автоматическое воспроизведение |
| `<< Начало` / `Конец >>` | Home / End | к первому / последнему шагу |

Если библиотеки не установлены, программа сообщает об этом, а сам алгоритм всё равно работает.

Для анимации в каждом файле есть версия алгоритма с суффиксом `_steps` (например, `dijkstra_steps`). Она выполняет те же действия, что и основная функция, но после каждого действия сохраняет «снимок» состояния и текстовое пояснение. Плеер просто показывает эти снимки по очереди.

## 1. Алгоритм Дейкстры (`dijkstra.py`)

### Задача
Дан взвешенный граф с **неотрицательными** весами рёбер и стартовая вершина `s`. Требуется найти длины кратчайших путей от `s` до всех остальных вершин и сами пути.

### Идея
Алгоритм «жадный»: на каждом шаге из ещё не обработанных вершин выбирается та, до которой текущее известное расстояние минимально. Так как веса неотрицательны, это расстояние уже нельзя улучшить — оно окончательное.

### Как работает
1. Всем вершинам присваивается расстояние `dist[v] = ∞`, стартовой — `dist[s] = 0`.
2. Стартовая вершина кладётся в очередь с приоритетом (двоичную кучу `heapq`) с ключом 0.
3. Пока очередь не пуста:
   - достаётся вершина `u` с минимальным расстоянием; если она уже обработана, пропускается;
   - вершина `u` помечается как обработанная;
   - для каждого ребра `u → v` с весом `w` выполняется **релаксация**: если `dist[u] + w < dist[v]`, то `dist[v]` обновляется, `prev[v] = u`, а `v` кладётся в кучу с новым расстоянием.
4. По массиву предков `prev` восстанавливается путь: идём от целевой вершины назад к стартовой и разворачиваем результат.

### Почему нельзя отрицательные веса
Если есть ребро отрицательного веса, вершина, уже признанная «окончательной», может позже получить меньшее расстояние, и жадный выбор становится неверным. Для таких графов используется алгоритм Беллмана-Форда.

### Формат ввода
```
Граф ориентированный? (y/n): n
Количество рёбер: 3
  ребро 1: A B 1
  ребро 2: B C 2
  ребро 3: A C 5
Стартовая вершина: A
```
Имена вершин — любые слова без пробелов, вес — неотрицательное число (целое или дробное). Для неориентированного графа каждое ребро добавляется в обе стороны.

### Вывод
Для каждой вершины — расстояние от стартовой и путь (`inf` и «нет пути», если вершина недостижима).

### Визуализация
- стартовая вершина — жёлтая, достижимые — голубые, недостижимые — серые;
- над каждой вершиной подписано расстояние `d` от стартовой;
- на рёбрах подписаны веса;
- красным выделено **дерево кратчайших путей** (рёбра `prev[v] → v`): путь до любой вершины — это путь по красным рёбрам от стартовой.

### Пошаговая анимация
Шаги: извлечение вершины из кучи → релаксация каждого исходящего ребра.
- оранжевая вершина — текущая (только что извлечена из кучи), зелёные — обработанные (расстояние окончательное), голубые — в куче (расстояние найдено, но может уменьшиться), белые — ещё не достигнуты;
- проверяемое ребро: зелёное — релаксация улучшила расстояние, оранжевое — не улучшила;
- внизу слева — текущее содержимое кучи в виде пар `(d, вершина)` и список обработанных вершин. В куче могут оставаться устаревшие записи — при извлечении они пропускаются, это тоже показано отдельным шагом.

## 2. Алгоритм Тарьяна (`tarjan.py`)

### Задача
В ориентированном графе найти все **компоненты сильной связности (КСС)**. Это максимальные множества вершин, в которых из любой вершины достижима любая другая.

### Идея
Выполняется один обход в глубину (DFS). Каждой вершине присваиваются два числа:
- `index[v]` — порядковый номер, под которым вершина была впервые посещена;
- `low[v]` — минимальный `index` среди вершин, достижимых из поддерева `v` (включая саму `v`) и ещё находящихся в стеке.

Вершина `v`, для которой `low[v] == index[v]`, является **корнем** КСС: из её поддерева нельзя «подняться» выше неё.

### Как работает
1. Для каждой ещё не посещённой вершины запускается `strongconnect(v)`:
   - `v` получает `index[v] = low[v] = счётчик`, счётчик увеличивается;
   - `v` кладётся в стек.
2. Для каждого ребра `v → w`:
   - если `w` ещё не посещена, рекурсивно вызывается `strongconnect(w)`, затем `low[v] = min(low[v], low[w])`;
   - если `w` уже в стеке (значит, она в той же формирующейся компоненте), выполняется `low[v] = min(low[v], index[w])`;
   - если `w` посещена, но уже не в стеке, она принадлежит уже найденной КСС и ребро игнорируется.
3. После обработки всех рёбер: если `low[v] == index[v]`, вершины снимаются со стека до `v` включительно. Снятые вершины и образуют одну КСС.

Компоненты выдаются в порядке обратной топологической сортировки графа компонент.

### Формат ввода
```
Вершины через пробел (можно оставить пустым — возьмутся из рёбер): a b c d
Количество рёбер: 3
  ребро 1: a b
  ребро 2: b a
  ребро 3: b c
```
Список вершин нужен, чтобы учесть изолированные вершины (без рёбер), каждая из которых образует отдельную КСС.

### Вывод
Количество компонент и состав каждой из них.

### Визуализация
- каждая КСС окрашена в свой цвет, состав компонент указан в легенде;
- рёбра внутри компоненты нарисованы цветом компоненты;
- рёбра между разными компонентами — серым пунктиром. Если «стянуть» каждую компоненту в одну вершину, по этим рёбрам получится ациклический граф (конденсация).

### Пошаговая анимация
Шаги: вход в вершину → обработка каждого ребра → возврат из рекурсии с пересчётом `low` → проверка, является ли вершина корнем КСС.
- оранжевая вершина — текущая, жёлтые — лежат в стеке, белые — не посещены; вершины найденных КСС окрашиваются в цвет своей компоненты;
- под каждой посещённой вершиной подписано `index / low` — видно, как `low` уменьшается при возврате из рекурсии и при встрече вершины из стека;
- чёрное ребро — обрабатываемое сейчас, синие — текущая цепочка рекурсивных вызовов;
- внизу слева — содержимое стека, путь рекурсии и найденные КСС.

## 3. Алгоритм Форда-Фалкерсона (`ford_fulkerson.py`)

### Задача
Дана сеть: ориентированный граф, где у каждого ребра есть **пропускная способность** `c(u, v)`, а также выделены исток `s` и сток `t`. Требуется найти **максимальный поток** из `s` в `t`, то есть наибольшее количество «вещества», которое можно передать, не превышая пропускных способностей и соблюдая сохранение потока в промежуточных вершинах.

### Ключевые понятия
- **Остаточная сеть** — показывает, сколько ещё можно пропустить по каждому ребру. Для ребра `u → v` с потоком `f` остаточная способность равна `c(u, v) − f`. Кроме того, появляется **обратное ребро** `v → u` с остаточной способностью `f`: через него можно «отменить» ранее пущенный поток.
- **Увеличивающий путь** — путь из `s` в `t` в остаточной сети, по всем рёбрам которого остаточная способность больше нуля.

### Как работает
1. Изначально поток нулевой, остаточная сеть совпадает с исходной.
2. Обходом в глубину (DFS) ищется увеличивающий путь из `s` в `t`.
3. Если путь найден:
   - вычисляется его «узкое место» — минимальная остаточная способность на пути;
   - для каждого ребра пути `u → v` остаточная способность уменьшается на эту величину, а у обратного ребра `v → u` увеличивается;
   - величина узкого места прибавляется к общему потоку.
4. Шаги 2–3 повторяются, пока увеличивающий путь существует.

По **теореме Форда-Фалкерсона** поток максимален тогда и только тогда, когда в остаточной сети нет увеличивающего пути. Величина максимального потока равна пропускной способности минимального разреза.

Итоговый поток по ребру вычисляется как `c(u, v) − остаточная(u, v)`.

Замечание: при целых пропускных способностях алгоритм всегда завершается. Если искать пути обходом в ширину (BFS), получается алгоритм Эдмондса-Карпа со сложностью O(V · E²).

### Формат ввода
```
Количество вершин: 4
Количество рёбер: 5
  ребро 1: 0 1 3
  ребро 2: 0 2 2
  ребро 3: 1 2 1
  ребро 4: 1 3 2
  ребро 5: 2 3 3
Исток: 0
Сток: 3
```
Вершины нумеруются от `0` до `n − 1`, пропускные способности — неотрицательные целые числа. Повторно введённые рёбра между одной и той же парой вершин складываются.

### Вывод
Величина максимального потока, поток по каждому ребру в виде «поток / пропускная способность» и минимальный разрез.

**Минимальный разрез** находится после завершения алгоритма: S — множество вершин, достижимых из истока в остаточной сети, T — все остальные. Рёбра из S в T заполнены полностью, и сумма их пропускных способностей равна максимальному потоку.

### Визуализация
- вершины расположены слоями слева направо по удалённости от истока `s`, сток подписан `t`;
- на рёбрах подписано «поток/пропускная способность», толщина ребра пропорциональна потоку;
- синие рёбра несут поток, серые — пустые;
- вершины стороны истока (S) — зелёные, стороны стока (T) — оранжевые;
- рёбра минимального разреза выделены красным пунктиром.

### Пошаговая анимация
Каждая итерация показана двумя шагами: найденный увеличивающий путь с его узким местом → сеть после пропускания потока по этому пути. Последний шаг — итоговый поток и минимальный разрез.
- оранжевые рёбра и жёлтые вершины — увеличивающий путь;
- фиолетовый пунктир — путь проходит по **обратному ребру**, то есть часть ранее пущенного по нему потока отменяется (например, на сети `0→1, 0→2, 1→2, 1→3, 2→3` с ёмкостями 1 вторая итерация идёт по пути `0 → 2 → 1 → 3` и отменяет поток по ребру `1→2`);
- внизу слева — текущая величина потока.

## 4. Алгоритм Грэхема (`graham.py`)

### Задача
Дано множество точек на плоскости. Требуется построить их **выпуклую оболочку**, то есть наименьший выпуклый многоугольник, содержащий все точки. Наглядно: если вбить гвозди в точки и натянуть вокруг них резинку, она примет форму выпуклой оболочки.

### Основной инструмент — векторное произведение
Для трёх точек `O`, `A`, `B`:

```
cross(O, A, B) = (A.x − O.x)·(B.y − O.y) − (A.y − O.y)·(B.x − O.x)
```
- `> 0` — поворот `O → A → B` налево (против часовой стрелки);
- `< 0` — поворот направо;
- `= 0` — точки лежат на одной прямой.

### Как работает
1. **Опорная точка.** Выбирается самая нижняя точка (при равенстве — самая левая). Она гарантированно лежит на оболочке.
2. **Сортировка.** Остальные точки сортируются по полярному углу относительно опорной (`atan2`), а при равных углах — по расстоянию до неё.
3. **Обход со стеком.** Опорная точка кладётся в стек. Для каждой следующей точки `p`:
   - пока две верхние точки стека и `p` образуют **не левый** поворот (`cross ≤ 0`), верхняя точка снимается со стека, потому что она лежит внутри оболочки или на её стороне;
   - `p` кладётся в стек.
4. После обхода в стеке остаются вершины выпуклой оболочки в порядке против часовой стрелки.

Каждая точка добавляется в стек и снимается с него не больше одного раза, поэтому сам обход занимает O(n), а общая сложность O(n log n) определяется сортировкой.

Коллинеарные точки на сторонах оболочки не включаются: остаются только «угловые» вершины.

### Формат ввода
```
Количество точек: 5
  точка 1: 0 0
  точка 2: 2 0
  точка 3: 1 1
  точка 4: 2 2
  точка 5: 0 2
```
Координаты — целые или дробные числа, разделённые пробелом или запятой.

### Вывод
Список вершин выпуклой оболочки в порядке обхода против часовой стрелки.

### Визуализация
- опорная точка отмечена жёлтой звездой;
- серые пунктирные лучи из опорной точки показывают, по какому углу сортируются точки;
- оболочка закрашена, её вершины красные и пронумерованы в порядке обхода;
- остальные точки (внутренние и лежащие на сторонах) — серые.

### Пошаговая анимация
Шаги: выбор опорной точки → сортировка по углу → для каждой точки проверка поворотов и работа со стеком → итоговая оболочка.
- синие номера у точек — порядок обхода после сортировки;
- красная ломаная — текущее содержимое стека (кандидаты в оболочку);
- оранжевым кружком выделена рассматриваемая точка;
- пунктиром показана проверяемая тройка точек: зелёный — левый поворот (точка добавляется в стек), оранжевый — правый поворот или прямая (вершина стека удаляется, она помечена крестиком);
- внизу слева — содержимое стека.
